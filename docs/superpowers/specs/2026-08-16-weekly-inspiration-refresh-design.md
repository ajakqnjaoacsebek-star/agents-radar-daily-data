# 每周灵感候选更新设计

## 目标

在不调用 DeepSeek 的前提下，每周从公开来源捕捉最新的工具、AI 项目、开源项目、工作流、产品动态和数字生活发现；新增内容直接进入每日推荐池，但每周实际推荐的新增动态候选最多 3 条。

## 数据边界

- `config/inspiration-catalog.json` 继续保存长期、人工核验的宝藏库，不由自动任务改写。
- `config/inspiration-signals.json` 保存每周抓取的动态候选，保留最近 90 天，按稳定 ID 和来源 URL 去重。
- 动态候选必须有 HTTPS 原始链接、来源标签、日期和可追溯的程序生成文案；抓取失败不清空旧信号。
- 每日卡片可从动态池或长期池选择；动态候选每周最多成功选中 3 次，剩余日期从长期池或历史动态候选补足。

## 来源与安全

- 每周工作流只访问公开的 GitHub Search、Hacker News Algolia 和 Hugging Face API，不需要新账号或模型 Key。
- 外部标题和描述只作为已绑定来源的展示文案，不允许模型改写事实；无效 URL、空标题和重复来源直接剔除。
- 动态卡片带 `generatedBy: fallback`，表示没有使用 LLM，不把自动抓取信号伪装成人工核验长期条目。

## 失败与恢复

- 任一来源失败时保留上次 `inspiration-signals.json`，其他来源仍可合并。
- 所有来源都失败时，周任务不覆盖文件；每日灵感继续从旧动态池和长期库生成。
- 记录每周动态推荐计数，跨周自动归零；兼容已有只有 `recent` 字段的状态文件。

## 验收标准

- 每周刷新可合并新候选、去重并裁剪 90 天外信号。
- 每日连续运行时，动态候选最多被推荐 3 次/周；第四次自动回退到长期候选。
- 每日和每周工作流均不设置 `DEEPSEEK_API_KEY`，且无模型调用路径。
- 现有长期候选、历史卡片、日报工作流和网站读取逻辑不受影响。
