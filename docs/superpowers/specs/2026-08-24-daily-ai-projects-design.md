# AI日报「每日 AI 项目」设计

日期：2026-08-24  
状态：已确认并实施
涉及系统：Agents Radar 数据仓库、GitHub Actions、AI日报私人阅读站、独立私有偏好仓库

## 1. 背景与目标

在现有「每日灵感」之外新增完全独立的「AI项目」分区，每天推荐一个值得尝试或了解的项目。它的核心目的不是堆积项目链接，也不是把用户带进系统课程，而是：

1. 通过项目学习可以迁移到其他场景的 AI 能力；
2. 持续打开开发思路，发现“AI 原来还能这样用”；
3. 逐渐从小项目过渡到能解决真实问题的完整系统；
4. 偶尔接触商业项目、大型系统和 AI 跨领域实践，扩展能力边界。

推荐既可以来自经过核验的真实开源项目、产品案例或工作流，也可以是系统原创的项目构想。原创构想必须明确标注，不能把尚不存在的功能、价格、效果或商业结果描述成事实。

## 2. 非目标

- 不把「AI项目」混入「每日灵感」的数据文件、任务或页面；两者完全独立。
- 不做按章节推进的系统课程。
- 不只推荐聊天框、摘要器等可被 Codex 一次对话直接替代的空壳小助手。
- 不承诺项目必然能完成、获得用户或赚钱。
- 不因为日历时间过去就自动提高推荐难度。
- 不让模型自由编造项目事实、来源、价格、限制或能力。
- 第一版不增加“进行中项目”、团队协作、公开分享或社交功能。

## 3. 推荐内容口味

### 3.1 选择原则

候选项目按以下顺序评价：

1. **实用价值**：能否用于工作、生活、学习或真实业务；
2. **学习价值**：能否学会一种可在其他项目复用的 AI 能力；
3. **灵感价值**：能否带来新鲜、有趣或跨领域的项目视角；
4. **商业价值**：是否可能成为服务、产品或收入实验；商业价值不等于收益承诺。

实用与学习优先，但项目不必同时满足全部条件。一个暂时不实用、但能明显打开脑洞并带来学习价值的项目仍可入选。

### 3.2 初始软比例

按滚动 30 天约 30 条推荐计算：

- 16～18 条偏实用；
- 7～9 条偏能力学习；
- 3～5 条偏脑洞与趣味；
- 大约每 7 条包含 1 条 AI 跨领域实践；
- 四星及以上的大型商业项目通常每 30 天不超过 1 条；低难度商业项目不受此限制。

这些标签允许重叠，也不作为页面上的醒目分类。它们只用于内部选题和平衡，不是不可改变的硬配额。收藏、不感兴趣、已完成记录和用户明确要求可以调整后续权重，但系统仍保留少量跨方向探索，避免把用户困在已有偏好中。

### 3.3 允许的项目范围

- 个人生产力与日常工具；
- 学习、考试与个人知识应用；
- 浏览器自动化、Agent 和多模型协作；
- 数据分析、内容产品和行业情报；
- 电商、客户服务、销售与本地商业服务；
- 游戏、桌宠、互动体验等脑洞项目；
- AI 与三维、音乐、视频、设计、硬件、研究等领域结合；
- 需要长期实践的 AI 技能型项目。

涉及重要决策、朋友肖像、招聘平台自动操作、支付或其他敏感场景时，卡片必须标注准确性、隐私、授权、平台规则和人工确认要求。不得把高考志愿、求职、交易等高影响决策完全交给自动化系统。

## 4. 推荐节奏与候选池

### 4.1 双候选池

1. **近期池**：每周从 GitHub、Hacker News、Product Hunt、Hugging Face、官方更新、真实案例等公开来源收集新信号。
2. **长期库**：人工核验的经典开源项目、工作流、商业实验、原创构想和跨领域项目，包含可直接发布的完整中文文案。

每周刷新任务可以使用一次 DeepSeek 对近期来源做归类、去噪和候选草拟。模型只能基于输入证据工作；真实项目的标题、链接和事实必须重新绑定到已抓取来源。模型不可替换来源链接。刷新失败时保留旧近期池，不覆盖为坏数据。

### 4.2 每日选择

每天由独立工作流选择并发布一个项目。每日选择默认不调用模型，而是根据候选元数据、近期去重、滚动比例、个人反馈和难度偏好进行确定性评分。

选择时依次：

1. 剔除缺少必要字段或真实项目缺少来源的候选；
2. 排除近期已经推荐的同一候选；
3. 降低与近期项目过于相似的候选权重；
4. 应用“不感兴趣”原因形成的轻量偏好；
5. 应用内容软比例与当前难度范围；
6. 保留少量跨方向探索；
7. 选出分数最高的合格候选。

若近期池、偏好读取或选择逻辑失败，从长期库选择一条近期未重复的完整候选。AI项目失败不能阻断每日灵感、技术日报或其他产物。

### 4.3 独立性

AI项目使用独立的：

- 候选目录和状态文件；
- 每周刷新工作流；
- 每日发布工作流；
- 输出 JSON；
- Manifest 可见性字段；
- 网站入口与历史页；
- 测试和失败降级逻辑。

不得复用每日灵感的“最新日期”判断，避免一种内容缺失时影响另一种内容。

## 5. 难度模型与成长校准

### 5.1 两层难度

系统不把五颗星当成永久绝对上限，而是分开保存：

1. **项目复杂度原始信息**：技术复杂度、外部依赖、预计投入、成本与风险、不确定性；
2. **个人当前难度**：相对于用户当前能力映射为 1～5 星。

内部保留可扩展的数值分数和各维度，页面第一版显示五颗星。未来可以调整阈值或扩展为十级，不需要重写历史项目。

### 5.2 初始星级解释

- 一星：跟随 Codex 可在数小时内看到完整效果，外部依赖少；
- 二星：需要一两个 API、简单自动化或界面，路线清楚；
- 三星：包含数据、前后端、自动任务或部署等多个部分；
- 四星：商业原型或复杂系统，外部平台、可靠性和运营要求较多；
- 五星：长期产品级项目，可能涉及真实用户、资金、合规或多个高风险依赖。

页面必须解释“难在哪里”，不能只显示星星。

### 5.3 推荐难度

- 日常推荐以一至三星为主；
- 四星项目低频出现；
- 五星项目极少出现，除非用户主动提高难度或出现特别值得了解的项目；
- 高难度项目不必缩成小助手，但必须指出最不确定的关键假设和建议的可行性测试；
- 能力不会因时间自动升级，只根据已完成项目和用户明确调整而变化。

### 5.4 历史评级

项目记录保留：

- 首次推荐时评级；
- 收藏时评级；
- 完成时评级；
- 按当前能力重新计算的评级。

已完成库参与能力校准。Codex 能检查项目时依据代码、文档和实际产物评级；不能检查时使用用户确认和说明。仅点击按钮但缺少任何完成说明时，不得大幅提高能力等级。

## 6. 数据结构

### 6.1 候选项目

每个候选至少包含：

- 稳定 `candidateId`；
- 来源类型：`verified-existing` 或 `original-concept`；
- 项目名称和一句话功能；
- 简短总结；
- 最终产物；
- 值得做的原因；
- 可学习能力列表；
- 真实用途或商业可能；
- 最优先验证的假设与建议测试；
- 成本、账号、硬件、地区、隐私、平台规则等风险；
- 内部内容标签和跨领域标签；
- 项目复杂度各维度与基准分数；
- 原始来源链接与核验日期；原创构想的来源链接可为空，但必须有原创标记；
- 可用于失败降级的完整中文文案。

### 6.2 每日项目产物

每日写入：

`digests/YYYY-MM-DD/daily-ai-project.json`

文件包含候选的稳定事实快照、当日个人难度星级、难度说明、生成方式和来源。真实项目的链接只能来自候选库，不能由选择模型修改。

Manifest 每个日期新增独立字段 `hasAiProject`。AI项目日期选择只读取该字段。

### 6.3 私人数据仓库

新的私有 GitHub 仓库保存：

- 收藏项目；
- 不感兴趣记录及可选原因；
- 已完成项目；
- 外部导入项目；
- 难度偏好与能力校准信息；
- schema 版本和更新时间。

数据以稳定 ID 去重，并保留推荐项目的必要快照，避免公共候选以后变化导致收藏卡失效。

## 7. 网站体验

### 7.1 AI项目历史页

网站顶部新增醒目的「AI项目」入口。页面结构沿用现有阅读体验：

- 左侧按日期显示每日推荐；
- 右侧显示选中日期的项目卡片；
- 未读项目不会阻止后续日期生成；
- 当天缺失时给出明确提示，不回退成错误日期。

### 7.2 项目卡片

卡片先显示项目名称、一句话总结、来源标记和难度星级，再展开六部分：

1. 最终做成什么；
2. 为什么值得做；
3. 能学会什么；
4. 真实用途或商业可能；
5. 最该先验证的假设；
6. 成本与风险。

操作包括：

- **详细了解**：真实项目打开核验来源；原创构想打开站内扩展说明；
- **感兴趣后继续**：生成或复制一份可交给 Codex 的项目启动简报，不自动创建或执行项目；
- **收藏 / 已收藏**；
- **不感兴趣**：可以直接提交，也可选择“对我没用、没意思、太重复、投入不值得”或填写自定义原因；
- **标记已完成**。

所有外链在新标签页安全打开。写操作必须显示保存中、成功、失败和可重试状态。

### 7.3 藏宝库

AI项目页放置醒目的「藏宝库」入口。藏宝库采用项目画廊，不以日期为主：

- 每个收藏项目是一张独立小卡；
- 正面突出项目名称、一句话功能和当前难度；
- 日期、完整六点、来源和学习能力进入详情层；
- 点击整张卡或“继续了解”进入详情；
- 支持取消收藏和标记完成。

### 7.4 已完成库

已完成库同样采用画廊：

- 推荐项目可以从卡片或藏宝库标记完成；
- 用户自创并在 Codex 完成的项目可以导入；
- 网站提供表单导入名称、说明和链接；
- 用户可以对 Codex 说“把这个项目导入已完成库”，由 Codex 检查当前项目、整理卡片并写入私有仓库；
- 卡片详情包含实际完成内容、使用技术、学习能力、证据链接、完成日期、完成时评级和当前评级；
- 已完成项目自动参与能力校准。

第一版不增加单独的“进行中库”。收藏表示想保留，完成表示已有成果。

## 8. 私人保存、备份与账号迁移

### 8.1 自动保存

网站服务端通过环境变量中的仓库级凭证读写私有 GitHub 仓库。凭证只授予目标私有仓库内容读写权限，不发送到浏览器，也不写入源码、JSON、日志或构建产物。

保存采用读取当前文件 SHA、更新、冲突重试的方式，避免覆盖较新的收藏。浏览器可以先显示临时状态，但只有远程写入成功后才显示最终“已收藏”或“已完成”；失败时保留可重试提示。

### 8.2 导出和导入

藏宝库与已完成库提供完整 JSON 导出和导入：

- 导出不包含任何凭证；
- 导入先校验 schema、稳定 ID 和必要字段；
- 重复记录按更新时间合并，不静默覆盖更新内容；
- 导入前显示将新增、更新和跳过的数量。

### 8.3 换 ChatGPT 账号

私人 GitHub 仓库独立于 ChatGPT 账号。更换账号时：

1. 在新账号下重新部署站点；
2. 为新站点配置同一私有仓库和新生成的最小权限凭证；
3. 站点自动恢复收藏、反馈和已完成项目；
4. 若暂时不上线，仍可保留本地导出文件和 GitHub 仓库。

旧站点链接不能作为永久备份；账号失效后可能仍存在但无法管理或通过身份验证。

## 9. 自动化与成本

- 每周候选刷新最多进行一次模型整理调用；
- 每日选择和发布不调用模型；
- DeepSeek 无余额、接口错误或来源抓取失败时，保留旧近期池并从长期库发布；
- AI项目自动任务独立于每日灵感和已暂停的技术日报；
- 任务日志只记录候选 ID、数量和错误类型，不输出 API Key、GitHub token 或私人反馈内容。

## 10. API 与错误处理

网站服务端提供单用户私有接口，用于：

- 读取收藏、反馈、已完成项目和能力配置；
- 收藏与取消收藏；
- 保存不感兴趣及可选原因；
- 标记完成；
- 导入外部完成项目；
- 导出和导入完整备份。

由于站点当前仅允许所有者账号访问，第一版按单用户数据模型实现。任何接口均需通过站点私有访问层，且服务端不接受客户端指定任意仓库、分支或文件路径。

错误分为：

- 公共推荐暂不可用；
- 私人仓库读取失败；
- 保存冲突并已重试；
- 保存失败，需要用户重试；
- 导入文件无效；
- 外部来源失效。

页面使用可理解的中文提示，不展示 token、堆栈或内部请求标识。

## 11. 测试计划

### 11.1 推荐生成

- 双池合并与稳定 ID 去重；
- 真实候选缺少来源时剔除；
- 原创候选明确显示原创标记；
- 来源链接不能被模型输出替换；
- 每日只生成一个项目；
- 近期重复和连续相似项目被降权；
- 滚动 30 天软比例在可用候选足够时符合范围；
- 跨领域项目大约每 7 条出现一次；
- 高难度大型商业项目受频率限制；
- 模型、来源或偏好失败时从长期库降级；
- AI项目异常不影响每日灵感文件和工作流。

### 11.2 难度与成长

- 五星显示由可配置阈值生成；
- 修改阈值可重新计算当前评级；
- 历史推荐、收藏和完成评级不丢失；
- 未来扩为十级时旧数据无需迁移重写；
- 已完成项目参与校准，单纯时间流逝不升级能力；
- 缺少完成证据时不会产生大幅能力跃升。

### 11.3 私人数据

- 收藏、取消收藏和不感兴趣写入私有仓库；
- 可选反馈原因支持为空、预设或自定义；
- GitHub 写入冲突可安全重试；
- 写入失败不显示虚假成功；
- 私人仓库凭证不会进入客户端包、日志或导出文件；
- 导出、校验、合并导入和重复去重；
- 推荐项目与外部项目均可进入已完成库。

### 11.4 网站

- AI项目默认打开最新可用项目日期；
- 日期历史和详情加载正确；
- 藏宝库和已完成库以项目画廊显示；
- 小卡正面突出名称和一句话功能；
- 详情显示六点、评级和来源；
- 操作状态、失败提示和重试清晰；
- 现有每日灵感和站点导航不回归；
- 移动端和桌面端均可使用。

### 11.5 端到端

1. 手动运行每周刷新，确认候选池更新或安全保留旧池；
2. 手动运行每日 AI 项目，确认数据仓库生成独立 JSON 和 Manifest 字段；
3. 部署私人站点，确认历史页、六点卡片和外链；
4. 收藏、反馈、完成和导入外部项目，确认私有仓库记录正确；
5. 导出后清空测试数据，再导入恢复；
6. 人为制造 AI 项目失败，确认每日灵感仍能独立运行。

## 12. 初始内容准备

上线前长期库至少准备 120 条完整候选，以支持每天一更、近期去重和多方向比例。候选至少覆盖：

- 实用工具与自动化；
- AI 能力练习；
- 脑洞互动项目；
- 简单商业实验；
- 少量大型商业系统；
- AI 跨领域实践。

长期库中的每条候选都必须有完整六点文案、难度原始维度、风险说明和失败降级可用文案。不能用泛化模板批量填充看似不同、实际相同的项目。

## 13. 发布顺序

1. 定义 schema、选择规则和难度模型并以测试固定；
2. 建立初始长期库和每周候选刷新；
3. 增加独立每日工作流与 Manifest 字段；
4. 创建私有收藏仓库和最小权限凭证；
5. 实现网站服务端私人数据接口；
6. 实现 AI项目历史页、藏宝库和已完成库；
7. 实现导出、导入与 Codex 导入说明；
8. 完成测试、手动端到端运行和 Sites 发布。

## 14. 验收标准

- 连续运行时每天产生一个可读、非空、来源合规的 AI 项目；
- 推荐内容以实用和学习为主，同时保留低频脑洞、商业和跨领域项目；
- 大多数项目难度处于一至三星，且星级可重新校准和扩展；
- 用户能收藏、反馈、标记完成和导入外部完成项目；
- 藏宝库和已完成库以名称与功能为核心的画廊展示；
- 私人数据自动写入独立私有 GitHub 仓库，并可导出、导入和换账号恢复；
- AI项目任何失败均不阻断每日灵感；
- 现有私人站点的每日灵感、历史数据和访问控制不受影响。
